# Enforce Role Hierarchy on Edit/Delete

## Goal
Prevent users from editing/deleting their own account or accounts at the same level or higher.
Hierarchy: Manager > Supervisor > Staff

## Rules
- **Manager**: Can edit/delete Supervisors and Staff only (not other Managers, not self)
- **Supervisor**: Can edit/delete Staff only (not Supervisors, not Managers, not self)
- **Staff**: Cannot edit/delete anyone

## Changes

### 1. User Model (`app/Models/User.php`)
Add a role level helper:
```php
public function roleLevel(): int
{
    return match($this->role) {
        self::ROLE_MANAGER => 3,
        self::ROLE_SUPERVISOR => 2,
        self::ROLE_STAFF => 1,
        default => 0,
    };
}
```

### 2. UserController (`app/Http/Controllers/UserController.php`)

**`edit()`** — Add checks:
- Can't edit self
- Can't edit same level or higher role

**`update()`** — Add checks:
- Can't update self
- Can't update same level or higher role

**`destroy()`** — Already prevents self-deletion, add:
- Can't delete same level or higher role

Helper method to check if target is manageable:
```php
private function canManageUser(User $target): bool
{
    $currentUser = auth()->user();
    if ($target->id === $currentUser->id) return false;
    return $currentUser->roleLevel() > $target->roleLevel();
}
```

### 3. Index View (`resources/views/users/index.blade.php`)
Hide Edit/Delete buttons for users that can't be managed (same level or higher, or self).

### 4. Edit View (`resources/views/users/edit.blade.php`)
- Role dropdown only shows roles strictly lower than current user's role (already handled by `$availableRoles`)
- Password fields are only shown when editing a user with a strictly lower role level
  - Manager editing Staff → password fields visible
  - Manager editing Supervisor → password fields visible
  - Manager editing Manager → blocked entirely (can't manage)
  - Supervisor editing Staff → password fields visible
  - Any user editing same/higher level → blocked entirely (can't manage)

Pass `$canChangePassword` boolean from controller to view (true when target role level < current user role level).

## Files to modify
- `app/Models/User.php` (add `roleLevel()`)
- `app/Http/Controllers/UserController.php` (add `canManageUser()`, update `edit/update/destroy`, pass `$canChangePassword`)
- `resources/views/users/index.blade.php` (hide buttons for unmanageable users)
- `resources/views/users/edit.blade.php` (conditionally show password fields)

## Verification
- Manager can edit/delete Supervisors and Staff, but not other Managers or self
- Supervisor can edit/delete Staff, but not other Supervisors, Managers, or self
- Staff sees no edit/delete buttons at all
- Password fields only shown when editing a user with strictly lower role
- Trying to access `/users/{id}/edit` directly returns 403 for unmanageable users
- Trying to update password for same/higher level user is blocked server-side
