## 1. Authentication Flow

### Public Routes (no auth required)
| Method | URI | Controller | Purpose |
|--------|-----|-----------|---------|
| GET | `/login` | `LoginController@showLoginForm` | Show login page |
| POST | `/login` | `LoginController@login` | Authenticate user |
| POST | `/logout` | `LoginController@logout` | Destroy session |
| POST | `/register` | `RegisterController@register` | Self-register (no role selection) |
| GET | `/forgot-password` | `ForgotPasswordController@showForm` | Request password reset |
| POST | `/forgot-password` | `ForgotPasswordController@submit` | Create pending reset token |
| GET | `/password-recovery/{token}` | `PasswordRecoveryController@showForm` | Show reset form (only if approved) |
| POST | `/password-recovery/{token}` | `PasswordRecoveryController@updatePassword` | Set new password |

### Login Flow
```
GET /login → login.blade.php
POST /login → validate(email+password) → Auth::attempt()
  → success: LoginLog::create(success:true) → redirect intended (or home)
  → fail: LoginLog::create(success:false) → back with error
```

### Register Flow
```
POST /register → validate(name, email unique, password min:4)
  → User::create(name, email, hashed_password) → Auth::login() → redirect invoices.index
```
Note: Registration has no role field — default is no role (likely null/empty). Only admins/managers/supervisors can create users with roles via `UserController`.

### Forgot Password Flow (Admin-approval based, NOT email-based)
```
GET  /forgot-password → auth.forgot-password.blade.php
POST /forgot-password → find User by email → PasswordResetRequest::create(pending, token)
  → redirect to /password-recovery/{token}

GET  /password-recovery/{token} → auth.password-recovery.blade.php (shows form only if status=pending/approved)
POST /password-recovery/{token} → requires status=approved → update password → delete token → redirect login
```
The approval is done by Admin via `Admin\PasswordResetController`:
```
GET  /admin/password-resets → list all pending requests
POST /admin/password-resets/{id}/approve → set status=approved
POST /admin/password-resets/{id}/reject → set status=rejected
```

## 4. Invoice CRUD Flow

### 4a. Invoice List (`GET /invoices` → `invoices.index`)
- Query with optional filters: `search` (nomor/nama_penjual/nama_pembeli), `status`, `from`, `to`
- Paginated (10 per page)
- **Bulk actions:** `POST invoices/bulk-action` → mark paid/unpaid/delete multiple invoices

### 4b. Create Invoice
```
GET /invoices/create → invoices.create.blade.php
  - Loads chartOfAccounts (non-header accounts)
```
```
POST /invoices → validate → store:
  1. Validate all fields (nomor unique, tanggal, signature_type, seller/buyer info, items[])
     - If signature_type=qr: require qr_image upload
     - If signature_type=hand: require signature_data (drawn)
  2. Compute item subtotals: subtotal = max((harga × qty) - diskon, 0)
  3. Sum total
  4. Build QR payload: base64(JSON{nomor, tanggal, npwp/nama/alamat_penjual, npwp/nama/alamat_pembeli, total, currency})
  5. If qr_image uploaded → store as data URI
  6. Invoice::create() → items()->create() for each item
  7. JournalService::postInvoice() → double-entry journal posting
  8. ActivityLog::create() → "Membuat invoice {nomor}"
  9. Redirect to invoices.show
```

### 4c. Show Invoice (`GET /invoices/{id}` → `invoices.show`)
- Loads `items.chartOfAccount`
- Displays invoice detail with actions: Edit, Delete, Preview, PDF, QR, Mark Paid/Unpaid, Duplicate

### 4d. Edit Invoice
```
GET /invoices/{id}/edit → invoices.edit.blade.php
  - Loads invoice + items.chartOfAccount + chartOfAccounts list
```
```
PUT /invoices/{id} → validate (nomor unique except current) → update:
  1. Recompute total + item subtotals
  2. Build new QR payload
  3. Update invoice fields + qr_payload
  4. Delete all old items → recreate new items
  5. JournalService::postInvoice() (reverses old + posts new)
  6. ActivityLog::create()
  7. Redirect to invoices.show
```

### 4e. Delete Invoice (`DELETE /invoices/{id}`)
```
1. JournalService::reverseInvoice() → delete journal entries
2. Invoice::delete()
3. ActivityLog::create()
4. Redirect to invoices.index
```

### 4f. Mark Paid/Unpaid
```
POST /invoices/{id}/mark-paid → markAsPaid() → ActivityLog → back
POST /invoices/{id}/mark-unpaid → markAsUnpaid() → ActivityLog → back
```

### 4g. Duplicate Invoice
```
GET /invoices/{id}/duplicate → generate new nomor via InvoiceNumberService (INV-YYYY-NNNN)
  → clone invoice data with new nomor + today's date + unpaid status
  → clone all items
  → ActivityLog
  → Redirect to invoices.edit (of the new invoice)
```

**Routes:** `resource('users')` — index, create, store, edit, update, destroy

**Authorization:** Admin, Manager, or Supervisor can access. Role hierarchy enforced:
- Admin (level 4) → can manage all roles
- Manager (level 3) → can create/edit Supervisor + Staff only
- Supervisor (level 2) → can create/edit Staff only
- Staff (level 1) → can only edit self

| Action | Notes |
|--------|-------|
| `index` | List all users, paginated |
| `create` | Show available roles based on current user's level |
| `store` | Create user with role, password confirmation required |
| `edit` | Self-edit (no role change) or manage others |
| `update` | Self-edit requires current_password; role change only by higher-level users |
| `destroy` | Cannot delete self; can only delete lower-level users |

## 12. Accounting/Journal Service

`JournalService` performs **double-entry bookkeeping** on invoice create/update/delete:

**On create/update (`postInvoice`):**
1. Reverse all existing entries for this invoice
2. For each invoice item with a chart_of_account: **Debit** that account for the item subtotal
3. **Debit** Piutang Dagang (1-1131) for the invoice total
4. **Credit** Penjualan Kredit Lokal (4-1121) for the invoice total

**On delete (`reverseInvoice`):**
- Deletes all journal entries where reference_type=Invoice and reference_id=invoice.id

## 14. Invoice Number Generation

`InvoiceNumberService::generate()` uses a `invoice_counter` table with row-level locking:
- Format: `INV-YYYY-NNNN` (e.g., INV-2026-0001)
- Atomic increment via `lockForUpdate()`

## 15. QR Code System

Two modes for signature:
1. **QR (DJP-provided):** User uploads a QR image from DJP (tax authority). Stored as data URI. Served directly when accessed.
2. **Hand signature:** User draws signature. Stored as `signature_data` (string). QR payload is generated server-side linking to the PDF.

**QR payload format:** `base64(JSON)` containing nomor, tanggal, seller/buyer info, total, currency.
**QR image fallback:** If no DJP image, generates QR code via `Endroid\QrCode` that links to the PDF URL.
