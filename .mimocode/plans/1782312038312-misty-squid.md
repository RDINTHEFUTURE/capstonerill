# Fix PDF Faktur Pajak Overflow — Attempt 2

## Root Cause (Remaining)

After attempt 1 fixed `box-sizing` and reduced the container to 186mm, the inner table columns still use explicit mm widths that sum to 186mm — but the container's inner content area is only ~180mm (186mm minus padding 8px×2 + border 1.5px×2 ≈ 5.6mm). Tables overflow because column widths exceed available space.

**Key insight:** The `width: 100%` on tables already constrains them to the container. The problem is the explicit per-column `width: Xmm` values which force the columns wider than the table's computed width.

## Fix

**File:** `resources/views/invoices/cetakfaktur.blade.php`

### Step 1: Add `table-layout: fixed` to all tables
This forces columns to respect the declared widths strictly rather than auto-expanding.

### Step 2: Remove all explicit mm-based column widths from items table
Remove `style="width: Xmm"` from `<th>` elements. With `table-layout: fixed` and `width: 100%`, columns auto-distribute proportionally. The last column (Harga Jual) can keep `text-align: right`.

### Step 3: Remove mm-based widths from summary table
Replace `.summary-label { width: 131mm }` and `.summary-value { width: 55mm }` with percentage-based widths:
- `.summary-label`: `width: 72%`
- `.summary-value`: `width: 28%`

### Step 4: Remove mm-based widths from footer grid
Replace `.legal-notice { width: 120mm }` and `.signature-area { width: 65mm }` with:
- `.legal-notice`: `width: 65%`
- `.signature-area`: `width: 35%`

### Step 5: Keep serial-bar table flexible
The inline `style="width: 55mm"` on the serial bar label td should be changed to a percentage: `width: 35%`.
